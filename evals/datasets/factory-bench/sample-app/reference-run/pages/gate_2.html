spec_wi-due-dates-overdue: Optional due date on todos, overdue flag, and GET /todos/overdue

After this merges, a client can send an optional calendar due_date (YYYY-MM-DD) when creating a todo; every todo the API returns carries due_date (null when unset) and a boolean overdue computed at response time; and GET /todos/overdue returns exactly the overdue todos in ascending id order. A todo is overdue if and only if it is open and its due_date is strictly before the current UTC calendar date (confirmed by the owner, human_comments.md (3)). This serves the metrics 'Overdue visibility' and 'Backwards compatibility' (title-only clients and the three existing tests are unchanged). The goal is missed if any flag disagrees with the rule, the overdue list differs from the flagged todos, or a malformed due_date is stored.

spec.md

spec_wi-due-dates-overdue (revision 2): Optional due date on todos, overdue flag, and GET /todos/overdue

Work item wi-due-dates-overdue | outcome out_4e93d2a0d0 | decomposition dec_4e93d2a0d0r1 | size S

Goal

After this merges, a client can send an optional calendar due_date (YYYY-MM-DD) when creating a todo; every todo the API returns carries due_date (null when unset) and a boolean overdue computed at response time; and GET /todos/overdue returns exactly the overdue todos in ascending id order. A todo is overdue if and only if it is open and its due_date is strictly before the current UTC calendar date (confirmed by the owner, human_comments.md (3)). This serves the metrics 'Overdue visibility' and 'Backwards compatibility' (title-only clients and the three existing tests are unchanged). The goal is missed if any flag disagrees with the rule, the overdue list differs from the flagged todos, or a malformed due_date is stored.

Non-goals

  • Changing or clearing a due date after creation (no PATCH/PUT); un-completing a todo; reminders; filtering, sorting

    • or paginating by due date.

  • Datetime due dates, per-user timezones, or any timezone other than UTC.
  • Persistence, a database, response-model clean-up, any change to service_manifest.json, pyproject.toml, .github/ or

    • CI, or a GET /todos/{todo_id} route.
